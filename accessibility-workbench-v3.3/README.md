# 웹접근성 테스트 워크벤치 v3

## v3에서 달라진 점
v2의 iframe 실행 미리보기를 제거했습니다.

이제 구조는 다음과 같습니다.

- 워크벤치 창: 검사 결과와 자동 진단을 보는 콘솔
- 테스트 창: 실제 그래프 HTML을 별도 브라우저 창으로 실행

따라서 그래프 페이지 안에서 직접:
- 그래프 카드 클릭
- Tab / Shift+Tab
- 방향키
- Enter / Space
- Esc
- 범례 버튼 조작
을 테스트할 수 있습니다.

## 사용 방법
1. `index.html` 실행
2. 그래프 HTML 파일 선택
3. `별도 테스트 창 열기`
4. 새 창에서 검사할 그래프 카드 클릭
5. 실제 키보드로 조작
6. 워크벤치 창으로 돌아와 `현재 테스트 창 검사`
7. 다른 그래프로 이동 후 4~6 반복

## 자동으로 보는 항목
- 실행 중 ECharts 인스턴스
- tabindex / 실제 focus
- role / accessible name
- aria-keyshortcuts
- Arrow / Enter / Space / Escape 이벤트 처리 단서
- 대체 데이터 표
- 범례 aria-pressed 실제 토글
- 포커스 스타일 단서
- aria-live
- 페이지 전체 가로 오버플로
- 포커스 요소 화면 이탈
- overflow 영역에서의 포커스 요소 잘림
- 너무 작은 조작 영역
- 열린 dialog의 이름 연결

## 주의
자동검사는 센스리더/NVDA의 실제 음성 결과를 대신하지 않습니다.
워크벤치 왼쪽의 직접 조작 체크 항목과 실제 보조기기 테스트를 병행하세요.

200% / 400% 버튼은 CSS zoom 기반 보조 테스트입니다.
최종 확대 접근성 검증은 브라우저 자체 확대 200% / 400%에서도 확인하세요.

## 팝업
브라우저가 새 창을 막는 경우 해당 파일/페이지의 팝업을 허용해야 합니다.


## v3.1 청각장애 검사 추가
검사 관점에 `청각장애`가 추가되었습니다.

자동검사:
- video / audio 요소 존재 여부
- video의 captions/subtitles track
- audio 콘텐츠의 텍스트 대체 필요 표시
- autoplay + controls 조합
- JavaScript 오디오 재생 코드(new Audio, .play(), AudioContext) 탐지 후 소리 전용 알림 여부 수동확인 표시

수동검사:
- 영상 자막/수어 등 대체수단
- 음성 콘텐츠 대본
- 경고/상태를 소리만으로 전달하지 않는지
- 자동재생 소리의 정지/음소거 가능 여부

### 청각장애 테스트의 핵심
청각장애 접근성은 별도의 '청각장애 브라우저'를 흉내 내는 테스트가 아니라,
`소리를 완전히 끈 상태에서도 동일한 정보와 기능을 이해하고 사용할 수 있는가`를 확인하는 방식입니다.


## v3.2 스크린리더 음성 시뮬레이션
추가 기능:
- 현재 테스트 창의 포커스 요소를 음성으로 읽기
- 테스트 창에서 Tab으로 포커스가 이동할 때 자동 읽기 ON/OFF
- 스크린리더 관점 목록의 각 항목별 `🔊 읽기`
- 음성 읽기 정지
- 읽기 속도 0.6x ~ 1.6x
- role / accessible name / aria-pressed / aria-expanded / aria-selected / aria-checked / disabled / aria-keyshortcuts를 한국어 문장으로 조합해 읽기

### 중요
이 기능은 브라우저 Web Speech API(SpeechSynthesis)를 이용한 시뮬레이션입니다.
실제 NVDA, 센스리더, VoiceOver가 읽는 문장과 순서가 완전히 같다고 보장하지 않습니다.

권장 사용법:
1. 먼저 `자동 읽기 ON` 상태로 테스트 창에서 Tab 탐색
2. 차트 진입 시 제목·역할·단축키 안내가 이해되는지 듣기
3. 범례 버튼에서 aria-pressed 상태가 읽히는지 듣기
4. 최종 검증은 실제 센스리더/NVDA/VoiceOver로 반복
